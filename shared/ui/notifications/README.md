# Система уведомлений (WebSocket + API)

## Описание

Система уведомлений предоставляет возможность получения и отображения уведомлений в реальном времени через WebSocket соединение. Поддерживает различные типы уведомлений, связанных с подписками и платежами. Использует API endpoints для получения истории уведомлений и управления ими.

## Архитектура

### Компоненты

1. **NotificationWebSocketService** (`shared/lib/websocket/notification-websocket.service.ts`) - центральный сервис для управления WebSocket соединением и состоянием уведомлений
2. **useNotifications** (`shared/lib/hooks/useNotifications.ts`) - хук для работы с уведомлениями
3. **Notifications** (`shared/ui/notifications/Notifications.tsx`) - компонент отображения уведомлений
4. **ScrollArea** (`shared/ui/notifications/ScrollArea.tsx`) - компонент с возможностью подгрузки при скролле
5. **Типы уведомлений** (`shared/ui/notifications/types.ts`) - определение типов уведомлений

## Функциональность

### Получение уведомлений

- Подключение к WebSocket серверу при аутентификации пользователя
- Автоматическая переподка при разрыве соединения
- Получение уведомлений в реальном времени через WebSocket
- Загрузка истории уведомлений с сервера через API

### Типы уведомлений

Система поддерживает следующие типы уведомлений:

- `SUBSCRIPTION_ACTIVATED` - Активация подписки: "Ваша подписка активирована и действует до XX.XX.XXXX"
- `PAYMENT_WARNING` - Предупреждение о списании платежа: "Следующий платеж у вас спишется через X дней"
- `SUBSCRIPTION_EXPIRY_7_DAYS` - Окончание подписки через 7 дней: "Ваша подписка истекает через 7 дней"
- `SUBSCRIPTION_EXPIRY_1_DAY` - Окончание подписки через 1 день: "Ваша подписка истекает через 1 день"

### Возможности

- Отображение количества непрочитанных уведомлений
- Отметка уведомлений как прочитанных (одиночно или все сразу)
- Удаление уведомлений
- Подгрузка истории уведомлений при скролле
- Пагинация (показ уведомлений за последний месяц)
- Использование next-intl для отображения времени

## Использование

### В компоненте:

```tsx

// В шапке приложения
const Header = () => {
  return (
    <header>
      {/* другие элементы */}
      <Notifications />
    </header>
  );
};
```

### Внутреннее использование:

Компонент автоматически:
- Подключается к WebSocket при аутентификации
- Загружает историю уведомлений с API
- Обновляет счетчик непрочитанных уведомлений
- Обрабатывает действия пользователя (отметка как прочитанное, удаление)

## API взаимодействие

Компонент использует следующие API эндпоинты:

- `GET /notifications/{cursor}` - получение уведомлений с пагинацией
- `PUT /notifications/mark-as-read` - отметка уведомлений как прочитанные
- `DELETE /notifications/{id}` - удаление уведомления

## WebSocket протокол

Сообщения от сервера должны соответствовать следующему формату:

```json
{
  "type": "notification",
  "payload": {
    "id": 1,
    "message": "Текст уведомления",
    "isRead": false,
    "createdAt": "2023-01-01T00:00:00.000Z"
  }
}
```

Также поддерживаются:

- `unread_count` - обновление количества непрочитанных уведомлений
- `bulk_notifications` - массовая загрузка уведомлений
- `notification_deleted` - удаление уведомления

## Структура данных

```ts
interface NotificationsView {
  id: number;
  message: string;
  isRead: boolean;
  createdAt: string;
}
```

## Обработка ошибок

- При проблемах с подключением к WebSocket показывается ошибка
- При ошибках API сохраняется предыдущее состояние
- Автоматическая повторная попытка подключения
- Использование next-intl для форматирования времени вместо TimeAgo

## Стили

Компонент использует SCSS модули для стилизации. Доступны следующие классы:

- `.trigger` - контейнер для иконки уведомлений
- `.content` - выпадающий список уведомлений
- `.item` - отдельное уведомление
- `.unread` - непрочитанное уведомление
- `.header` - заголовок списка уведомлений
